# 文件上传指南

本文说明 MARS App 中 **选择本地文件 → 构建 FormData → 调用后台上传接口** 的完整流程，适用于 Android、iOS、HarmonyOS。

---

## 1. 整体流程

```
用户点击上传
  → react-native-document-picker 选文件
  → 得到 DocumentPickerResponse（uri / fileCopyUri / name / type）
  → ensureUploadablePath 确保沙箱可读路径（必要时 RNFS 兜底复制）
  → buildUploadFormDataFromPickedFile 构建 FormData
  → baseService.uploadFile（或业务 service）发 POST multipart 请求
  → 后台返回 UploadResult（fileId、fileUrl 等）
```

RN 不会在 JS 层手动 `readFile`：`FormData` 里 append 的 `{ uri, name, type }` 会交给**原生网络层**，由原生从 `uri` 读取文件二进制并拼进 `multipart/form-data`。

## 3. 上传 URL 配置

完整 URL = **Base URL** + **接口路径**。

### 3.1 Base URL

`src/constants/apiConfig.ts`：

```ts
export const API_BASE_URL = 'http://58.221.250.47:9443/api/app';
```

`apiClient` 创建 axios 实例时使用该值作为 `baseURL`。切换测试 / 生产环境时改这里。

### 3.2 接口路径

| 方法              | 路径                                                  | 完整示例                         |
| ----------------- | ----------------------------------------------------- | -------------------------------- |
| `uploadFile`      | `/file/upload`                                        | `{API_BASE_URL}/file/upload`     |
| `dictateFeedBack` | `/common/file/uploadFileMinio/upload/dictateFeedBack` | `{API_BASE_URL}/common/file/...` |

新增上传接口时，在对应 `src/services/*.ts` 中封装 `apiClient.post(path, formData, ...)`，与 JSON 接口写法一致，只是 body 为 `FormData`。

## 4. DocumentPicker 返回字段

选文件后常见字段：

| 字段          | 说明                                                                                  |
| ------------- | ------------------------------------------------------------------------------------- |
| `uri`         | 系统 picker 原始 URI（Android 可能为 `content://`，Harmony 可能为 `file://docs/...`） |
| `fileCopyUri` | 设置了 `copyTo` 时，复制到应用沙箱后的路径（**上传优先使用**）                        |
| `name`        | 原始文件名                                                                            |
| `type`        | MIME 类型，如 `application/pdf`                                                       |
| `size`        | 文件大小（字节）                                                                      |

**建议**：上传时始终设置 `copyTo: 'documentDirectory'`。若 `fileCopyUri` 为空（如鸿蒙相册图 `copyError`），`ensureUploadablePath` 会用 RNFS 再复制到沙箱；**不要**直接用 picker 的 `file://media/...` 上传。

Harmony 沙箱路径示例：

```
/data/storage/el2/base/haps/entry/files/<uuid>/picked.pdf
```

## 5. 构建 FormData

先通过 `ensureUploadablePath` 拿到上传可用的沙箱路径，再构建 FormData：

```ts
const {path} = await ensureUploadablePath(picked);

formData.append('file', {
  uri: path,
  name: picked.name ?? 'file',
  type: picked.type ?? 'application/octet-stream',
});
```

或直接：

```ts
const formData = await buildUploadFormDataFromPickedFile(picked, {
  fieldName: 'file', // 默认 'file'，需与后台字段名一致
  extraFields: {bizType: 'xxx'}, // 额外文本字段
});
```

调试时 `console.log(formData)` 可能看到 `_parts`，这是 RN 内部结构，**只含元数据不含文件内容**，属正常现象。

## 6. 单文件上传（最简示例）

```ts
import {isCancel, pickSingle, types} from 'react-native-document-picker';

import {uploadFile} from '@/services/baseService';
import {buildUploadFormDataFromPickedFile} from '@/utils/buildUploadFormDataFromPickedFile';

export async function pickOneAndUpload() {
  try {
    const picked = await pickSingle({
      type: [types.allFiles],
      copyTo: 'documentDirectory',
      allowMultiSelection: false,
    });

    const formData = await buildUploadFormDataFromPickedFile(picked);
    const res = await uploadFile(formData);

    if (!res.success) {
      throw new Error(res.message || '上传失败');
    }

    // res.data: UploadResult
    return res.data; // { fileId, fileUrl, ... }
  } catch (err) {
    if (isCancel(err)) {
      return null; // 用户取消
    }
    throw err;
  }
}
```

## 7. 多文件上传

后台若**不支持**一次请求多个文件，需循环单文件上传：

```ts
import {pick} from 'react-native-document-picker';

import {uploadFile} from '@/services/baseService';
import {buildUploadFormDataFromPickedFile} from '@/utils/buildUploadFormDataFromPickedFile';

export async function pickManyAndUpload() {
  const pickedList = await pick({
    type: [types.allFiles],
    copyTo: 'documentDirectory',
    allowMultiSelection: true,
  });

  const results = [];
  for (const picked of pickedList) {
    const formData = await buildUploadFormDataFromPickedFile(picked);
    const res = await uploadFile(formData);
    results.push(res.data);
  }
  return results;
}
```

Demo 中「选择单文件并上传」「选择多文件并上传」按钮即上述两种流程的可运行版本。

## 8. 业务接口示例

指令反馈等场景使用专用路径，FormData 构建方式相同：

```ts
import {dictateFeedBack} from '@/services/regulationService';
import {buildUploadFormDataFromPickedFile} from '@/utils/buildUploadFormDataFromPickedFile';

const formData = await buildUploadFormDataFromPickedFile(picked, {
  fieldName: 'file', // 以实际后台字段名为准
});
const res = await dictateFeedBack(formData);
```

## 9. 响应结构

`uploadFile` 返回 `Promise<ApiResponse<UploadResult>>`：

```ts
interface UploadResult {
  fileId: string;
  fileUrl: string;
  [key: string]: unknown;
}
```

外层还有 `success`、`code`、`message`，用法与其它 API 一致，见 [API 客户端响应指南](./API客户端响应指南.md)。

## 10. 鉴权与 Loading

- `apiClient` 会通过 `setTokenProvider` 注入的 Token 自动添加 `Authorization` 请求头，**未登录可能 401**。
- 默认参与全局 Loading（与 JSON 请求相同）；静默上传可传 `{ noLoading: true }` 到 service 层（需在 service 封装时透传 `config`）。

### Content-Type（multipart）

**不要**在 upload service 里手动设置 `Content-Type: multipart/form-data`。

`multipart/form-data` 必须带 `boundary`（例如 `multipart/form-data; boundary=----WebKitFormBoundary...`）。只写 `multipart/form-data` 不带 boundary 时，后台常无法解析文件体（400、空文件或 Network Error）。

项目已在 [`src/services/apiClient.ts`](../../src/services/apiClient.ts) 请求拦截器中统一处理：当 `data` 为 `FormData` 时自动清除 `Content-Type`（含实例默认的 `application/json`），由 RN 原生网络层生成带 boundary 的正确请求头。`uploadFile` / `dictateFeedBack` 只需传入 `formData`，无需额外 headers。

详见 [已知问题 #004 · FormData 上传 Content-Type](./已知问题.md)。Android 上登录正常但上传报「网络连接失败」见 **#007**。

## 11. 平台注意事项

| 平台        | 说明                                                                                                                                    |
| ----------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| **Harmony** | 务必 `copyTo: 'documentDirectory'`；上传路径用沙箱 `fileCopyUri`。DocumentPicker 鸿蒙 patch 见 `docs/file-viewer/鸿蒙集成与修复说明.md` |
| **Android** | 无 `fileCopyUri` 时 `uri` 常为 `content://`，RN 原生层仍可读取；有 `copyTo` 时优先沙箱路径                                              |
| **iOS**     | 路径多为 `file://...`，同样遵循 `fileCopyUri ?? uri`                                                                                    |

文件**预览**与**上传**可共用 picker，但预览见 `openPickedFilePreview`，上传见本文工具函数，职责分离。

## 12. 常见问题

### FormData 结构是否正确？

正确示例（log 中的 `_parts`）：

```js
[
  'file',
  {
    uri: '/data/storage/.../picked.pdf',
    name: '欢迎使用.pdf',
    type: 'application/pdf',
  },
];
```

`uploadFile` 会由原生层读取 `uri` 指向的文件，不是只把路径字符串发给后台。

### 上传失败：Network Error / 400

1. 检查 `API_BASE_URL` 是否可达、是否需 VPN / 内网。
2. **Android：登录 OK 但上传 Network Error、`fileCopyUri` 已有值** → 见 [已知问题 #007](./已知问题.md)（axios FormData / `setContentType(false)`）。
3. 确认已登录，Token 有效。
4. 确认后台字段名是否为 `file`（否则改 `fieldName`）。
5. 确认未手动设置 `Content-Type: multipart/form-data`（应交给 `apiClient` + RN 原生层自动带 boundary，见上文「Content-Type（multipart）」）。
6. 相册图片上传失败且 `fileCopyUri` 为 null：见 [已知问题 #005](./已知问题.md)（`ensureUploadablePath` RNFS 兜底）。
7. 报 `header name must be a non-empty string`（堆栈在 axios `xhr.js` `onloadend`）：见 [已知问题 #008](./已知问题.md)（Harmony 响应头解析；可能后台已成功）。

### 中文文件名

`name` 含中文时，部分后台对 `Content-Disposition` 编码处理不佳；文件内容通常仍能上传。必要时可在上传前将 `name` 改为 ASCII 文件名（需自行扩展工具函数或传参）。

### Demo 点了上传没反应

确认 `DocumentPickerDemo` 中没有调试用的 `return` 截断实际上传逻辑；应执行到 `await uploadFile(formData)`。
