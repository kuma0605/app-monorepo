# Harmony 文件选择与预览 — 集成与修复说明

> [!NOTE] > **版本适用性说明**：本文档最初基于 React Native 0.77 编写。当前项目已升级至 **React Native 0.82 (New Architecture)**，部分基础配置（如依赖版本、原生类命名等）可能已有更新。相关实现细节请以当前项目根目录配置及 `docs/harmonyos_packaging_guide.md` / `docs/harmony-and-android-file-viewer-patches.md` 为准。

> 日期：2026-05-19  
> 适用：React Native 0.77 + RNOH，`@react-native-ohos/react-native-document-picker@9.3.2`，`@react-native-ohos/react-native-file-viewer@2.3.0-beta.2`

本文记录 MARS App 为在 HarmonyOS 上**稳定选择文件并预览 PDF 等文档**所做的改动，以及 DevEco 构建 / 运行流程。

---

## 1. 背景与问题

### 1.1 期望行为

1. 用户通过 DocumentPicker 从系统文件管理器选 PDF
2. 调用 FileViewer 打开预览（PreviewKit 或系统「打开方式」）

### 1.2 官方示例在 Harmony 上的差异

JS 层 API 与 [react-native-file-viewer](./react-native-file-viewer.md) 一致，但鸿蒙原生实现存在以下问题：

| 问题                           | 表现                                                                            |
| ------------------------------ | ------------------------------------------------------------------------------- |
| DocumentPicker 返回错误 `uri`  | 把 `file://docs/storage/...` 转成 `/storage/...`，**丢失 picker 临时 URI 授权** |
| FileViewer 路由不当            | 对「外部路径」强制 `startAbility`，易出现 **unknown file: preview failed**      |
| PreviewKit 失败后错误 fallback | 沙箱文件 PreviewKit 失败仍走 `startAbility`，JS 侧 Promise 可能仍 resolve       |

### 1.3 构建 / 运行时踩坑

| 尝试                              | 结果                                                                                                       |
| --------------------------------- | ---------------------------------------------------------------------------------------------------------- |
| `oh-package.json5` **链源码目录** | 编译可通过，**启动崩溃**：`cannot find record '&@react-native-ohos/react-native-document-picker/ts&9.3.2'` |
| `hvigor assembleHar` 重打 `.har`  | 产出**字节码 har**，缺少 `ts.ts`，编译或运行均异常                                                         |
| macOS 打包 har 含 `._*` 文件      | C++ 编译报错 `._Props.cpp: source file is not valid UTF-8`                                                 |

**结论：** 必须使用 npm 自带的**源码格式 `.har`**（含 `ts.ts`、`src/main/cpp`），再把 patch 后的 ETS 写回 har。

## 3. 原生 Patch 详解

### 3.1 DocumentPicker（`documentPickerTurboModule.ts`）

**① 保留 picker 原始 URI**

```typescript
// 修复前
uri: fUri.path,

// 修复后
uri: uri,
```

`uri` 为系统返回的 `file://docs/storage/...`，带临时访问授权；`fUri.path` 仅为绝对路径，无法用于跨应用预览。

**② 沙箱副本使用 ASCII 文件名**

新增 `getSafeCopyFileName()`，`copyTo` 时复制为 `picked.pdf`、`picked.docx` 等，避免中文/特殊字符导致 PreviewKit 静默失败。

### 3.2 FileViewer（`RNFileViewerTurboModule.ts`）

相对 npm `2.2.0` 原版，patch 后模块主要增强：

| 能力                                      | 说明                                                                                          |
| ----------------------------------------- | --------------------------------------------------------------------------------------------- |
| `resolveFileTarget` / `resolvePreviewUri` | 统一解析 path、previewUri、mimeType                                                           |
| `/storage/` → `file://docs/storage/...`   | 外部存储路径转为文档 URI                                                                      |
| `isAppSandboxPath`                        | 区分应用沙箱与外部文档                                                                        |
| `preferSystemOpen`                        | 仅 `showOpenWithDialog` 或沙箱 txt 时走系统打开方式；**不再**因 `/storage/` 一律 startAbility |
| PreviewKit 失败处理                       | 沙箱路径失败时 **emit 错误**，不再错误 fallback 到 startAbility                               |
| `persistPermission`                       | 非沙箱 URI 仍尝试持久化读权限后再 PreviewKit                                                  |

## 4. `.har` 重打包机制

### 4.1 为什么需要 repack

- `patch-package` 修改的是 `node_modules/.../harmony/*/src/main/ets/*.ts`
- DevEco **实际编译的是** `harmony/entry/oh-package.json5` 引用的 **`*.har`**
- 因此必须把 patch 后的 ETS **写回 har**，Rebuild entry 才会带上修复

### 4.2 脚本行为（`scripts/repack-ohos-hars.sh`）

1. 解压 npm 自带 har（`package/` 前缀的 tar 包）
2. 覆盖 `documentPickerTurboModule.ts` / `RNFileViewerTurboModule.ts`
3. 排除 macOS `._*` / `.DS_Store` 后重新 tar
4. 写回 `node_modules/.../harmony/*.har`

`npm install` 的 `postinstall` 已串联：

```bash
patch-package && bash scripts/repack-ohos-hars.sh && git config core.hooksPath .githooks
```

### 4.3 手动重打（改 patch 后）

```bash
npm install                    # 或 npx patch-package && bash scripts/repack-ohos-hars.sh
cd harmony/entry && ohpm install
# DevEco: Sync → Clean → Rebuild → Run
npm run dev                    # Metro
```

## 5. Harmony 依赖配置

`harmony/entry/oh-package.json5` 必须使用 **`.har`**：

```json5
'@react-native-ohos/react-native-document-picker':
  'file:../../node_modules/@react-native-ohos/react-native-document-picker/harmony/document_picker.har',
'@react-native-ohos/react-native-file-viewer':
  'file:../../node_modules/@react-native-ohos/react-native-file-viewer/harmony/file_viewer.har',
```

**不要**写成 `.../harmony/document_picker` 或 `.../file_viewer` 源码目录。

## 6. JS 层预览策略

业务代码请使用 [`src/utils/openPickedFilePreview.ts`](../../src/utils/openPickedFilePreview.ts)，不要直接照搬官方「只 open `uri`」示例。

### 6.1 Harmony 分支逻辑

| 条件                           | 打开路径            | 选项                            | strategy                  |
| ------------------------------ | ------------------- | ------------------------------- | ------------------------- |
| 有 `fileCopyUri`               | 沙箱 `picked.{ext}` | 去掉 `showOpenWithDialog`       | `harmony-sandbox-preview` |
| 无副本                         | picker 原始 `uri`   | 强制 `showOpenWithDialog: true` | `harmony-picker-uri`      |
| 用户指定 `showAppsSuggestions` | picker `uri`        | 原样                            | `harmony-picker-uri`      |

DocumentPicker 调用固定带 `copyTo: 'documentDirectory'`，尽量拿到沙箱副本。

**预览标题：** 未传 `displayName` 时，自动使用 `picked.name`（原文件名）；沙箱磁盘文件名仍为 `picked.{ext}`（原生 patch，保证 PreviewKit 稳定）。显式传入 `displayName` 字符串或选项可覆盖标题。

### 6.2 最小用法

```typescript
import {openPickedFilePreview, isCancel} from '@/utils/openPickedFilePreview';

try {
  // 默认：预览标题 = 用户所选原文件名
  const result = await openPickedFilePreview();
  console.log(result.statusLines);

  // 自定义标题
  await openPickedFilePreview({displayName: '我的 PDF'});
} catch (e) {
  if (!isCancel(e)) throw e;
}
```

### 6.3 Demo 页

`src/screens/FileViewerDemo/index.tsx` 展示：

- 多种 `FileViewer.open` 选项（displayName、showOpenWithDialog、onDismiss 等）
- 每次操作后的 `uri` / `fileCopyUri` / `strategy` / `openPath` 诊断信息

## 9. 常见问题

### Q1：改 patch 后 Rebuild 无效？

```bash
bash scripts/repack-ohos-hars.sh
cd harmony/entry && ohpm install
# 必要时删除 harmony/oh_modules/.ohpm 下对应包缓存后再 ohpm install
# DevEco Clean + Rebuild
```

### Q2：启动崩溃 `cannot find record '&@react-native-ohos/.../ts&...'`？

`oh-package.json5` 误链了源码目录。改回 `.har` 并 `ohpm install`。

### Q3：C++ 报 `._Props.cpp` / UTF-8 错误？

har 打包带了 macOS 元数据。用 `repack-ohos-hars.sh`（已排除 `._*`）重打。

### Q4：ArkTS 编译报 `Cannot find name 'diff'`？

`RNFileViewerTurboModule.ts` 末尾误写入 git diff 行，删除即可；正常应只以 `}` 结尾。

### Q5：能否只用 `hvigor assembleHar`？

不建议。产出字节码 har，与 entry 期望的源码 har（含 `ts.ts`）不兼容。
