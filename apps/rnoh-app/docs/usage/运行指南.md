# 项目下载与运行指南

本指南将指导你如何快速上手 SAMRApp 的开发环境，完成克隆、安装并运行三端（iOS、Android、鸿蒙）流程。

## 0. 前置环境自检 (Prerequisites)

在开始运行前，请确保你的开发机已具备以下基础环境（若未安装，请联系项目负责人）：

| 工具                | 建议版本                        | 检查命令        |
| ------------------- | ------------------------------- | --------------- |
| **Node.js**         | 18.x 或 22.x                    | `node -v`       |
| **JDK**             | 17 (Zulu JDK)                   | `java -version` |
| **Android SDK**     | API 34+                         | -               |
| **DevEco Studio**   | 最新稳定版 (支持 HarmonyOS 5.0) | -               |
| **CocoaPods** (Mac) | 1.15+                           | `pod --version` |

## 1. 克隆与初始化

```bash
# 1. 克隆项目
git clone <项目地址>
cd SAMRApp

# 2. 安装依赖 (自动执行 patch-package)
npm install
```

### 1.1 统一换行符配置 (Windows/Mac 跨平台)

本项目为了规避不同操作系统环境（Mac/Windows）下的换行符冲突，统一采用 **LF** 换行符。项目中已配置了 [.gitattributes](file:///Users/dylan/CodeHub/rnoh_cross_mars/.gitattributes) 和 [.editorconfig](file:///Users/dylan/CodeHub/rnoh_cross_mars/.editorconfig)。

对于不同的场景，处理方式如下：

#### 场景 A：首次在项目中引入或修改 `.gitattributes` 配置（需提交版本库）

执行以下命令以重归一化 Git 仓库中的已有文件：

```bash
# 重归一化所有文件为 LF（.bat/.cmd 会自动保持 CRLF 以兼容 Windows 运行）
git add --renormalize .
git commit -m "chore: renormalize line endings to LF"
```

#### 场景 B：同事拉取（`git pull`）最新代码后，本地已有文件（如 `screens/` 下未修改的文件）在磁盘上依然是 CRLF

由于 Git 默认不会主动重新下载和重写本地未变更文件的磁盘换行符，所以即使仓库中已是 LF，同事本地磁盘上可能仍显示为 CRLF（尤其是 Windows 机器）。

此时需要**强制刷新本地磁盘上的工作区文件**。请按以下步骤执行（执行前请确保本地没有未保存/未提交的代码）：

```bash
# 1. 备份本地尚未提交的改动（如果有的话）
git stash

# 2. 清除本地缓存索引并强行重置（这会迫使 Git 重新把所有文件按最新的属性规范写回本地磁盘）
git rm --cached -r .
git reset --hard

# 3. 还原刚刚备份的修改
git stash pop
```

_注：项目已在 [.vscode/settings.json](file:///Users/dylan/CodeHub/rnoh_cross_mars/.vscode/settings.json) 中配置了 `"files.eol": "\n"`，VS Code 用户在编辑/保存文件时默认均会采用 LF。_

## 2. 核心环境变量配置

运行前请确保终端已配置以下变量（建议写入 `~/.zshrc` 或 `~/.bash_profile`）：

### macOS (zsh)

```bash
export RNOH_C_API_ARCH=1
export ANDROID_HOME=$HOME/Library/Android/sdk
export PATH=$PATH:$ANDROID_HOME/platform-tools
# 鸿蒙工具链 (hdc) - 路径视安装位置而定
export PATH="/Applications/DevEco-Studio.app/Contents/sdk/default/openharmony/toolchains:$PATH"
```

### Windows (PowerShell)

```powershell
$env:RNOH_C_API_ARCH = "1"
$env:ANDROID_HOME = "C:\Users\你的用户名\AppData\Local\Android\Sdk"
$env:Path += ";$env:ANDROID_HOME\platform-tools"
# 鸿蒙工具链 (hdc)
$env:Path += ";C:\Program Files\Huawei\DevEco Studio\sdk\default\openharmony\toolchains"
```

## 5. 鸿蒙 (HarmonyOS) 运行流程

由于项目基于 C-API 架构，鸿蒙端的运行必须遵循严格顺序：

### 第一步：执行 Codegen (必须)

每当添加或更新原生三方库时，必须运行此命令生成桥接代码：

```bash
npm run codegen
```

### 第二步：生成本地 Bundle

将 JS 代码编译并拷贝至鸿蒙原生目录：

```bash
npm run dev
```

### 第三步：DevEco Studio 编译运行

1. 打开 **DevEco Studio**，选择 `File -> Open`，打开项目根目录下的 `harmony` 目录。
2. **同步工程**：点击右上角的 `Sync Now` 或 `File -> Sync and Refresh Project`。
   ~~3. **配置签名**：`File -> Project Structure -> Signing Configs`，勾选 `Automatically generate signature`（需登录华为账号）。~~
3. **创建鸿蒙虚拟机**（首次运行需要）：`Tools -> Device Manager`，点击 `+` 创建一个新的虚拟设备，选择合适的设备型号和系统镜像，完成后点击 `Launch` 启动虚拟机。
4. **运行**：在顶部设备选择栏中选择已启动的虚拟机，点击绿色三角按钮运行 `entry` 模块。

### 第四步：Metro 热重载调试（可选）

如果需要”保存即生效”的热重载调试，在 **另一个终端** 保持 Metro 运行：

```bash
npm start
```

Metro 默认监听 `localhost:8081`，应用启动时会优先尝试连接 Metro，连接成功后热重载自动生效——编辑 JS/TS 代码并保存即可看到变化。

**模拟器**：无需额外配置，Metro 直接可达。

**物理设备端口转发**：鸿蒙真机无法直接访问电脑的 `localhost`，需要通过 `hdc` 转发端口：

```bash
hdc rport tcp:8081 tcp:8081
```

如果连接失败，也可以在应用内手动配置 Metro 地址：打开开发者菜单 → “Connect to Metro Server on Local Network”，输入电脑的局域网 IP 和端口（如 `192.168.1.100:8081`），然后重启应用。

> **注意**：如果新建文件后 Metro 报找不到模块，尝试清除缓存重启：`npx react-native start --reset-cache`。

## 8. Reactotron 调试

Reactotron 是 React Native 开发调试工具，用来在桌面端观察 App 运行时状态。接入后可以集中查看网络请求、日志输出、状态变化、AsyncStorage 等调试信息，比只看 Metro 控制台更直观，适合排查接口调用、登录态、缓存数据和开发环境问题。

项目根目录的 `ReactotronConfig.js` 负责初始化 Reactotron，并在 `index.js` 的开发环境中加载：

```js
if (__DEV__) {
  require('./ReactotronConfig');
}
```

当前配置示例：

```js
import Reactotron from 'reactotron-react-native';

Reactotron.configure({
  name: 'SAMRApp',
  host: '192.168.72.83', // 默认 localhost，但推荐使用本机 IP，避免 VPN 环境下连接失败
  port: 9090,
})
  .useReactNative()
  .connect();
```

### Android 连接方式

Reactotron 默认监听电脑本机的 `9090` 端口。Android 模拟器/真机如果使用 `localhost` 连接，需要先执行端口反向代理：

```bash
adb reverse tcp:9090 tcp:9090
```

如果 adb 同时识别到多个设备，会出现 `adb: more than one device/emulator`。先查看设备 ID：

```bash
adb devices
```

再指定设备执行：

```bash
adb -s <deviceId> reverse tcp:9090 tcp:9090
```

确认映射：

```bash
adb -s <deviceId> reverse --list
```

### 鸿蒙连接方式

鸿蒙模拟器默认也无法访问 `localhost`，需要通过 `hdc` 转发端口：

```bash
hdc rport tcp:9090 tcp:9090 (用于 Reactotron 调试)
```

转发后 `ReactotronConfig.js` 中 `host` 设为 `'localhost'` 即可。

鸿蒙真机无法使用 `localhost`，需要将 `host` 改为电脑的局域网 IP，并确保手机与电脑在同一 Wi-Fi 下。

### ⚠️ 重要：修改 host 连接 Reactotron

由于每个人的电脑 IP 不同，你需要将 `ReactotronConfig.js` 中的 `host` 修改为你本机的 **局域网 IP**。

1. 获取本机 IP (Mac): `ifconfig en0 | awk '/inet / {print $2}'`
2. 修改 `ReactotronConfig.js`:

```js
Reactotron.configure({
  name: 'SAMRApp',
  host: '你的局域网IP', // 例如 192.168.1.100
  port: 9090,
});
```

## 9. 故障排除 (Troubleshooting)

| 问题                        | 原因                    | 解决方法                                                  |
| --------------------------- | ----------------------- | --------------------------------------------------------- |
| `hdc` 或 `adb` 找不到命令   | 环境变量未配置          | 检查 `~/.zshrc` 并 `source`                               |
| 鸿蒙端启动白屏              | Bundle 未同步或 JS 报错 | 重新执行 `npm run dev`，查看 Metro 日志                   |
| `Codegen` 报错              | `node_modules` 不完整   | 删除 `node_modules` 重新 `npm i`                          |
| iOS `pod install` 失败      | 网络问题                | 使用代理或更换 RubyGems 源                                |
| Reactotron 连不上           | IP 不对或防火墙拦截     | 检查 `host` 配置及 9090 端口占用                          |
| 鸿蒙 Reactotron 连不上      | 端口未转发              | 执行 `hdc rport tcp:9090 tcp:9090 (用于 Reactotron 调试)` |
| 鸿蒙真机 Metro 热重载不生效 | 真机无法访问 localhost  | 执行 `hdc rport tcp:8081 tcp:8081`                        |
| Metro 报找不到新建文件      | 文件监听缓存未刷新      | `npx react-native start --reset-cache`                    |
