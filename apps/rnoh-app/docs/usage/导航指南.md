# React Navigation 导航与传参指南

本文档说明当前项目的导航结构、路由注册规范、Tab 与 Root 页面划分规则，以及首页业务路由的类型约定。

项目基于 React Navigation，普通平台使用 `@react-navigation/native-stack`，Harmony/RNOH 平台通过 `.harmony.tsx` 文件使用 `@react-navigation/stack`。

---

## 1. 当前导航结构

当前真实导航结构：

```text
RootStack
├── Auth                       登录页，全屏，无底部 Tab
├── Main                       底部 Tab 容器
│   ├── HomeTab                首页入口页，直接挂 HomeScreen
│   ├── MarketRegTab           市场监管入口页，直接挂 MarketRegScreen
│   ├── SmartRegTab            智慧监管入口页，直接挂 SmartRegScreen
│   └── MeTab                  我的入口页，直接挂 MeScreen
└── /Home/...                  首页业务全屏页，与 Main 同级，无底部 Tab
```

对应文件：

| 层级              | 文件                                              | 说明                               |
| ----------------- | ------------------------------------------------- | ---------------------------------- |
| RootStack         | `src/navigation/rootStack.tsx`                    | Android/iOS 等 native-stack 根导航 |
| RootStack Harmony | `src/navigation/rootStack.harmony.tsx`            | Harmony/RNOH JS Stack 根导航       |
| MainTabs          | `src/navigation/mainTabs.tsx`                     | 底部 Tab 配置                      |
| Root 页面注册表   | `src/navigation/rootStackScreenRegistry.tsx`      | 与 `Main` 同级的全屏业务页注册表   |
| 路由类型          | `src/navigation/types.ts`                         | 所有导航参数类型定义               |
| 顶栏样式          | `src/navigation/defaultSubStackScreenOptions.tsx` | 子页通用顶栏配置                   |

## 2. Root 页面和 Tab 页面如何区分

新增页面前，先判断页面应该放在哪一层。

| 页面类型                                         | 放置位置                   | 是否显示底部 Tab |
| ------------------------------------------------ | -------------------------- | ---------------- |
| 登录页、鉴权页                                   | RootStack                  | 否               |
| 底部 Tab 首页/入口页                             | MainTabs 内对应 Tab Screen | 是               |
| Tab 内二级页，仍希望保留底部 Tab                 | 未来按需新增对应 Tab Stack | 是               |
| 详情页、表单页、通知跳转页、需要全屏展示的业务页 | RootStack，与 `Main` 同级  | 否               |

原则：

1. **需要隐藏底部 Tab 的页面，注册到 RootStack。**
2. **需要保留底部 Tab 的二级页面，才新增对应 Tab Stack。**
3. 不推荐通过 `tabBarStyle: {display: 'none'}` 临时隐藏 Tab，优先通过导航层级表达产品意图。

---

## 3. 底部 Tab 约定

底部 Tab 定义在 `src/navigation/mainTabs.tsx`。

当前 Tab：

| Tab 名         | 页面     | Stack                               |
| -------------- | -------- | ----------------------------------- |
| `HomeTab`      | 首页     | `HomeScreen`，不再额外包 Stack      |
| `MarketRegTab` | 市场监管 | `MarketRegScreen`，不再额外包 Stack |
| `SmartRegTab`  | 智慧监管 | `SmartRegScreen`，不再额外包 Stack  |
| `MeTab`        | 我的     | `MeScreen`，不再额外包 Stack        |

Tab 路由类型定义在 `RootTabParamList` 中：

```typescript
export type RootTabParamList = {
  HomeTab: undefined;
  MarketRegTab: undefined;
  SmartRegTab: undefined;
  MeTab: undefined;
};
```

新增或删除 Tab 时，需要同步修改：

1. `src/navigation/types.ts` 的 `RootTabParamList`。
2. `src/navigation/mainTabs.tsx` 的 `Tab.Screen`。
3. Tab 图标资源与 `TAB_ICONS`。
4. 页面入口；只有需要 Tab 内 push/pop 时才新增对应 Stack 文件。

---

## 4. 单页面 Tab 为什么不再包 Stack

当前 `HomeTab`、`MarketRegTab`、`SmartRegTab`、`MeTab` 都直接挂载页面，不再额外包一层 Stack。

首要原则：**简单易懂，不做无收益的过度封装**。

判断规则：

- Tab 只有一个入口页：直接挂页面。
- Tab 内确实需要保留底部 Tab 的 push/pop：才加 Tab Stack。
- 进入后需要隐藏底部 Tab 的业务页：放 RootStack，不放 Tab Stack。

因此当前 Tab 结构是：

```text
RootStack
├── Main
│   ├── HomeTab -> HomeScreen
│   ├── MarketRegTab -> MarketRegScreen
│   ├── SmartRegTab -> SmartRegScreen
│   └── MeTab -> MeScreen
├── /Home/...       首页业务全屏页
├── /MarketReg/...  市场监管业务全屏页（后续按需新增）
├── /SmartReg/...   智慧监管业务全屏页（后续按需新增）
└── /Me/...         我的业务全屏页（后续按需新增）
```

Root 级全屏业务页类型说明：

| 类型                      | 作用                                                          |
| ------------------------- | ------------------------------------------------------------- | ---------- |
| `RootBusinessRouteParams` | Root 级业务页通用参数，当前为 `{id?: string}                  | undefined` |
| `HomeRootParamList`       | 首页模块 Root 级业务路由，使用 `/Home/...`                    |
| `MarketRegRootParamList`  | 市场监管模块 Root 级业务路由，使用 `/MarketReg/...`，当前为空 |
| `SmartRegRootParamList`   | 智慧监管模块 Root 级业务路由，使用 `/SmartReg/...`，当前为空  |
| `MeRootParamList`         | 我的模块 Root 级业务路由，使用 `/Me/...`，当前为空            |
| `RootStackParamList`      | `Auth` / `Main` + 四个模块 Root 级业务路由的合并类型          |

## 5. 新增 Root 级全屏业务页

适用于：详情页、表单页、从消息/通知进入的页面、进入后需要隐藏底部 Tab 的页面。

### 第一步：在 `src/navigation/types.ts` 中声明参数

先按页面所属模块，添加到对应的 Root ParamList：

```typescript
export type HomeRootParamList = {
  '/Home/NewBusinessDetail': RootBusinessRouteParams;
};

export type MarketRegRootParamList = {
  '/MarketReg/CompanyDetail': RootBusinessRouteParams;
};

export type SmartRegRootParamList = {
  '/SmartReg/RiskDetail': RootBusinessRouteParams;
};

export type MeRootParamList = {
  '/Me/ProfileDetail': RootBusinessRouteParams;
};
```

当前 `RootStackParamList` 已经合并了四个模块的 Root ParamList，所以新增路由后，RootStack 与 `navigation.navigate(...)` 类型会自动识别。

Root 级业务页统一使用可选 `{id?: string}` 参数。列表页可以忽略 `id`，详情页按需读取。这样消息列表跳转时可以统一写 `navigation.navigate(screen, {id})`，不需要先判断目标页是否一定使用 `id`。

### 第二步：在 `src/navigation/rootStackScreenRegistry.tsx` 中注册页面

按页面所属模块，放到对应分组：

- 首页：`ROOT_STACK_SCREENS_HOME_TAB`
- 市场监管：`ROOT_STACK_SCREENS_MARKET_REG_TAB`
- 智慧监管：`ROOT_STACK_SCREENS_SMART_REG_TAB`
- 我的：`ROOT_STACK_SCREENS_ME_TAB`

示例：

```typescript
const ROOT_STACK_SCREENS_MARKET_REG_TAB: RootStackScreenEntry[] = [
  {
    name: '/MarketReg/CompanyDetail',
    component: require('@/screens/MarketReg/CompanyDetail')
      .default as RootStackScreen,
    options: {title: '企业详情'},
  },
];
```

`name` 必须和 `src/navigation/types.ts` 中的路由名一致。`RootStack` 会自动遍历 `ROOT_STACK_SCREEN_REGISTRY` 注册这些页面。

### 第三步：从对应 Tab 入口页跳转

Tab 入口页使用 `RootTabScreenProps` 后，可以直接跳转 Root 级业务页：

```typescript
navigation.navigate('/Home/NewBusinessDetail', {id});
navigation.navigate('/MarketReg/CompanyDetail', {id});
navigation.navigate('/SmartReg/RiskDetail', {id});
navigation.navigate('/Me/ProfileDetail', {id});

// 消息列表这种动态路由也可以直接传 id
navigation.navigate(screen ?? '/Home/PendingWarn', {id: item.businessId});
```

页面 Props 示例：

```typescript
import type {RootTabScreenProps} from '@/navigation/types';

// 按当前页面所在 Tab 选择一个即可
type Props = RootTabScreenProps<'HomeTab'>;
// type Props = RootTabScreenProps<'MarketRegTab'>;
// type Props = RootTabScreenProps<'SmartRegTab'>;
// type Props = RootTabScreenProps<'MeTab'>;
```

`RootTabScreenProps` 的作用是：

- 保留当前 Tab 页自身的类型。
- 同时允许直接跳转 RootStack 上注册的全屏业务页。
- 避免每个 Tab 都单独封装一个 `navigateXxxBusinessRoute` helper。

## 6. 新增 Tab 内页面

当前 4 个 Tab 都直接挂入口 Screen，不再额外包 Tab Stack。

如果后续某个 Tab 确实需要“进入子页后仍保留底部 Tab”的 push/pop，再新增对应 Tab Stack。

但新增前先确认产品交互：

- 需要保留底部 Tab：可以新增 Tab Stack。
- 需要隐藏底部 Tab：不要新增 Tab Stack，直接注册到 RootStack。

不要为了“以后可能会有子页面”提前创建 Stack。

---

## 7. 跨 Tab 导航

当前 4 个 Tab 都直接挂入口 Screen，因此跨 Tab 只需要导航到目标 Tab。

```typescript
navigation.navigate('MarketRegTab');
navigation.navigate('SmartRegTab');
navigation.navigate('MeTab');
```

注意：跨 Tab 导航后，底部 Tab 会切换到目标 Tab。

如果未来某个 Tab 新增了 Tab Stack，并且确实需要跳转到该 Tab 内部子页，再使用 React Navigation 的嵌套 `navigate` 写法。当前项目没有这种真实场景，不在文档中提前固化示例。

## 10. 关于 `CompositeNavigationProp`

当前 `HomeScreen` 直接挂在 `HomeTab` 上，但它需要跳转到 RootStack 上的 `/Home/...` 页面。

运行时 React Navigation 支持向父级导航冒泡，因此可以正常跳转。

但 TypeScript 默认只知道当前页面属于 `RootTabParamList` 的 `HomeTab`，不知道它外层还有 `RootStackParamList`。

项目已在 `src/navigation/types.ts` 中提供通用类型 `RootTabScreenProps<RouteName>`，内部使用 `CompositeNavigationProp` 把 Tab 导航和 Root 导航组合起来。

因此 Tab 入口页可以直接使用：

```typescript
type Props = RootTabScreenProps<'HomeTab'>;
```

完整示例（Tab 入口页 / Screen 组件拿到 `navigation` props）：

```typescript
import React from 'react';
import {Button, View} from 'react-native';
import type {RootTabScreenProps} from '@/navigation/types';

type Props = RootTabScreenProps<'HomeTab'>;

export default function HomeScreen({navigation}: Props) {
  return (
    <View>
      <Button
        title="去待办"
        onPress={() => navigation.navigate('/Home/PendingWarn')}
      />
      <Button
        title="去企业信息（带 id）"
        onPress={() =>
          navigation.navigate('/Home/FoodFirmMessage', {id: 'biz-123'})
        }
      />
    </View>
  );
}
```

页面内最常用的跳转写法：

```typescript
navigation.navigate('/Home/PendingWarn');
navigation.navigate('/Home/FoodFirmMessage', {id: item.businessId});
```

如果不是 Screen 组件（拿不到 `props.navigation`），可以用 `useNavigation`：

```typescript
import React from 'react';
import {Button} from 'react-native';
import {useNavigation} from '@react-navigation/native';
import type {NavigationProp} from '@react-navigation/native';
import type {RootStackParamList} from '@/navigation/types';

export function GoPendingWarnButton() {
  const navigation = useNavigation<NavigationProp<RootStackParamList>>();
  return (
    <Button
      title="去待办"
      onPress={() => navigation.navigate('/Home/PendingWarn')}
    />
  );
}
```

如果后续其它 Tab 也需要直接跳 Root 级页面，复用同一个类型即可，例如 `RootTabScreenProps<'MarketRegTab'>`。

## 11. 传参规范

1. 参数保持轻量：

- 推荐传 `id`、`type`、`source` 等简单字段。
- 不推荐传完整对象、大数组或接口响应。

2. 页面自己根据参数拉取详情或读取缓存。
3. 所有路由参数必须在 `src/navigation/types.ts` 中声明。
4. 新增路由时，类型、注册表、跳转调用方需要同步更新。

---

## 12. 修改导航后的检查

修改公共导航模块后，至少执行：

```bash
npm run lint
```

涉及多个入口或平台差异时，还需要分别检查：

- 普通平台：`src/navigation/rootStack.tsx`、`src/navigation/mainTabs.tsx`、`src/navigation/rootStackScreenRegistry.tsx`。
- Harmony/RNOH：`rootStack.harmony.tsx`，以及是否存在对应平台差异文件。
