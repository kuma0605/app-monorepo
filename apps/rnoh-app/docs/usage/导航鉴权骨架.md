# 导航 / 登录骨架（React Native & RNOH：Android + HarmonyOS）

本文说明当前项目的导航与登录骨架、文件结构，以及“从 Tab 入口页跳转到全屏业务页”的组织方式。

---

## 目标与行为

- **未登录**：展示登录页（全屏、无 Tab）。
- **已登录**：展示主界面（Bottom Tabs，4 个 Tab）。
- **退出登录**：在“我的”页触发退出，回到登录页（不保留主界面返回栈）。
- **进入 Root 级业务页**：隐藏底部 Tab。
- **进入 Tab 内 Stack 页面**：如果未来新增 Tab Stack，则保留底部 Tab；当前没有 Tab 内 Stack。

---

## 导航分层

### 1) RootStack

RootStack 是应用最外层导航，当前负责：

- `Auth`：登录页。
- `Main`：底部 Tab 容器。
- `/Home/...`：首页模块全屏业务页，与 `Main` 同级，因此进入后不显示底部 Tab。

RootStack 不是只做登录态切换；它也承载明确需要脱离 TabBar 的全屏业务页。

### 2) MainTabs

MainTabs 是底部 Tab 容器，当前包含：

- `HomeTab`：直接挂 `HomeScreen`，不额外包 Stack。
- `MarketRegTab`：直接挂 `MarketRegScreen`，不额外包 Stack。
- `SmartRegTab`：直接挂 `SmartRegScreen`，不额外包 Stack。
- `MeTab`：直接挂 `MeScreen`，不额外包 Stack。

MainTabs 的职责是 Tab 切换，不直接承载 Root 级全屏业务页。

### 3) Tab Stack

当前没有 Tab 额外包 Stack。

Tab Stack 只在确实需要时再创建，适用于：

- 进入后仍希望保留底部 Tab 的页面。
- 模块内部列表页、设置页等确实需要保留 Tab 的场景。

如果页面进入后需要隐藏底部 Tab，应注册到 RootStack，而不是放在 Tab Stack 内。

---

## 跨端策略

由于 HarmonyOS 侧对 `react-native-screens` 的支持限制，本项目采取：

- **Android/iOS 等普通平台**：Root 使用 `@react-navigation/native-stack`。
- **HarmonyOS/RNOH**：Root 使用 `@react-navigation/stack`。

通过同名文件的 `.harmony.tsx` 实现平台分流，业务侧 import 路径不变。

## 文件结构（导航/登录相关）

```text

    RootNavigator.tsx              # 导航入口：渲染 RootStackNavigator
    rootStack.tsx                  # 普通平台：native-stack RootStack
    rootStack.harmony.tsx          # Harmony：JS stack RootStack
    rootStackScreenRegistry.tsx    # 与 Main 同级的 Root 级业务页注册表

    mainTabs.tsx                   # 4 个 Tab：首页/市场监管/智慧监管/我的

    MarketReg/
      index.tsx
```

## 从首页跳转到无 Tab 的业务页

首页业务子页注册到 RootStack，与 `Main` 同级。

示例：

```text
RootStack
├── Auth
├── Main
│   └── HomeTab -> HomeScreen
└── /Home/PendingWarn
```

Tab 入口页使用 `RootTabScreenProps` 后，可以直接跳转：

```typescript
navigation.navigate('/Home/PendingWarn');
```

需要参数的页面：

```typescript
navigation.navigate('/Home/FoodFirmMessage', {
  id: item.businessId,
});
```

这样进入目标页后不会显示底部 Tab。

首页 Root 级业务页统一接受可选 `{id?: string}` 参数，所以消息列表这种动态跳转可以直接写 `navigation.navigate(screen ?? '/Home/PendingWarn', {id: item.businessId})`，不需要先判断目标页是否使用 `id`。

如果其它 Tab 后续也要直接跳 Root 级页面，同样把页面 Props 定义成 `RootTabScreenProps<'对应Tab名'>`。

## 登录态切换

### 登录 → 进入主界面

推荐做法：用登录态驱动渲染，不直接 `navigate`。

- `LoginScreen` 登录成功后写入 Redux user 状态。
- `RootStackNavigator` 根据 `isLoggedIn` 渲染 `Auth` 或 `Main`。

优点：不会留下登录页返回栈。

### 退出登录 → 回到登录页

同样用登录态驱动：

- “我的”页点击退出后清空登录态。
- `RootStackNavigator` 自动切回 `Auth`。

---

## 常见约定

1. 新增页面前先判断：是否需要隐藏底部 Tab。
2. 需要隐藏 Tab：注册到 RootStack 的 `rootStackScreenRegistry.tsx`。
3. 需要保留 Tab 的二级页：再新增对应 Tab Stack。
4. 单页面 Tab 不再包 Stack，直接把 Screen 作为对应 Tab 的 component。
5. 修改导航相关文件后执行 `npm run lint`。
